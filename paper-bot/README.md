# PaperBot: בוט מסחר אוטומטי בכסף וירטואלי

בוט שמקבל איתותי מסחר מ־TradingView, מבצע אותם **בסימולטור פנימי** עם 10,000$ וירטואליים, ומציג הכול בלוח בקרה שנפתח באייפון.

> **אין כאן כסף אמיתי.** בפרויקט אין שום חיבור לברוקר או לבורסה. "פקודה" היא רק שורה בקובץ הנתונים של השרת. ראה [למה זה בטוח](#למה-זה-בטוח).

## איך זה עובד, בשלוש שורות

```
TradingView (Pine Script)  ──התראה (Webhook)──▶  השרת שלך בענן (FastAPI)  ──▶  סימולטור ← לוח בקרה באייפון
   מזהה מתי לקנות/למכור                          בודק סיסמה, כפילויות, מגבלות       כסף וירטואלי בלבד
```

1. **TradingView** מריץ את הסקריפט `pine/paperbot_signals.pine` על גרף. כשמופיע איתות, הוא שולח הודעה קטנה (JSON) לכתובת של השרת.
2. **השרת** בודק שההודעה באמת ממך (סוד משותף), שהיא לא כפולה ושהיא בתוך המגבלות.
3. **הסימולטור** "קונה" או "מוכר" בכסף וירטואלי, גובה עמלה ומפעיל Stop Loss.
4. **לוח הבקרה** מציג יתרה, רווח והפסד, פוזיציות והיסטוריית פקודות.

## מה יש בפנים

| יכולת | איך |
| --- | --- |
| יתרה התחלתית | 10,000$ (`STARTING_BALANCE`) |
| קנייה | לפי כמות (`qty`), סכום בדולרים (`usd`) או ברירת מחדל של 1,000$ |
| מכירה | `sell` מוכר הכול או כמות חלקית. אין מכירה בחסר (Short) |
| עמלות | 0.1% מכל פקודה (`FEE_RATE`) ועוד עמלה קבועה אופציונלית (`FEE_FIXED`) |
| Stop Loss | ברירת מחדל: 2% מתחת למחיר הקנייה. אפשר לשנות לכל פקודה, או מלוח הבקרה |
| הגבלת גודל פקודה | פקודה מעל 2,000$ נדחית (`MAX_ORDER_USD`) |
| הגבלת הפסד יומית | אחרי הפסד ממומש של 300$ ביום, קניות חדשות נחסמות עד מחר (`MAX_DAILY_LOSS_USD`). מכירות ו־Stop Loss ממשיכים לעבוד |
| אימות Webhook | כל הודעה חייבת לכלול את `WEBHOOK_SECRET` |
| מניעת כפילויות | אותה התראה (אותו `id`) שמגיעה פעמיים מבוצעת פעם אחת בלבד |
| מצב בדיקה | כפתורים בלוח הבקרה ששולחים אותות דמה בלי לחכות לשוק |
| לוח בקרה | מותאם לאייפון, מצב כהה ובהיר, ואפשר להוסיף אותו למסך הבית |

## המדריכים (לפי הסדר)

1. **[פריסה בענן](docs/DEPLOY.md)**: מעלים את השרת לאוויר מהאייפון, בלי להתקין כלום (בערך 10 דקות).
2. **[בדיקה](docs/TESTING.md)**: מוודאים שהכול עובד עם אותות דמה, לפני שמחברים את TradingView.
3. **[חיבור TradingView](docs/TRADINGVIEW.md)**: מוסיפים את הסקריפט ויוצרים התראה.

## למה זה בטוח

- **אין קוד של ברוקר.** הקוד לא מכיל שום ספרייה של ברוקר, בורסה או אפילו לקוח HTTP. השרת רק *מקבל* בקשות ולא שולח לשום מקום.
- **בדיקה אוטומטית שומרת על זה.** `tests/test_safety.py` נכשלת אם מישהו מוסיף ספרייה כזו או הגדרה שנראית כמו מפתח ברוקר. GitHub מריץ את הבדיקות בכל שינוי.
- **כל תשובה של השרת מסומנת `"simulated": true`.**
- **אף אחד לא יבקש ממך סיסמאות.** הסודות היחידים בפרויקט (`WEBHOOK_SECRET`, `DASHBOARD_TOKEN`) נוצרים אוטומטית אצל ספק הענן. הם שלך בלבד ואינם קשורים לשום חשבון כסף.

## מבנה הפרויקט

```
paper-bot/
├── app/
│   ├── main.py           השרת: Webhook, אימות, API ללוח הבקרה, מצב בדיקה
│   ├── simulator.py      הסימולטור: קנייה, מכירה, עמלות, Stop Loss, מגבלות
│   ├── storage.py        שמירת הנתונים (SQLite)
│   ├── config.py         ההגדרות (משתני סביבה)
│   └── static/           לוח הבקרה (דף אחד)
├── pine/paperbot_signals.pine   סקריפט ה־TradingView (Pine Script v6)
├── tests/                הבדיקות האוטומטיות
├── docs/                 המדריכים
├── requirements.txt      הספריות שהשרת צריך
├── Dockerfile            לספקי ענן אחרים (לא נדרש ב־Render)
└── .env.example          דוגמה לכל ההגדרות
```

`render.yaml` נמצא בתיקייה הראשית של הריפו, ומאפשר ל־Render להקים את הכול בלחיצה אחת.

## ההגדרות

כל ההגדרות הן משתני סביבה. ב־Render משנים אותן בלשונית **Environment** של השירות, והשרת מתעדכן לבד.

| משתנה | ברירת מחדל | מה הוא עושה |
| --- | --- | --- |
| `WEBHOOK_SECRET` | נוצר אוטומטית | הסוד ש־TradingView שולח. בלעדיו ה־Webhook נעול |
| `DASHBOARD_TOKEN` | נוצר אוטומטית | ה"סיסמה" של לוח הבקרה |
| `TEST_MODE` | `true` | מציג את כפתורי אותות הדמה |
| `STARTING_BALANCE` | `10000` | היתרה ההתחלתית ($) |
| `FEE_RATE` | `0.001` | עמלה כאחוז מהפקודה (0.001 = 0.1%) |
| `FEE_FIXED` | `0` | עמלה קבועה לפקודה ($) |
| `DEFAULT_ORDER_USD` | `1000` | גודל קנייה כשהאות לא מציין כמות |
| `MAX_ORDER_USD` | `2000` | פקודה גדולה מזה נדחית |
| `MAX_DAILY_LOSS_USD` | `300` | הפסד יומי שאחריו קניות נחסמות (0 = בלי מגבלה) |
| `DEFAULT_STOP_LOSS_PCT` | `2` | Stop Loss ברירת מחדל, באחוזים (0 = בלי) |
| `ALLOW_FRACTIONAL` | `true` | לאפשר חלקי יחידה (קריפטו). `false` = מניות שלמות בלבד |
| `DEDUP_WINDOW_SECONDS` | `86400` | כמה זמן לזכור התראות כדי לזהות כפילויות |
| `TIMEZONE` | `America/New_York` | מתי מתחיל "יום" לצורך מגבלת ההפסד היומית |
| `DB_PATH` | `data/paperbot.db` | איפה נשמרים הנתונים |

## פורמט ההודעה (למי שרוצה לכתוב אסטרטגיה משלו)

```json
{"secret": "...", "action": "buy", "symbol": "AAPL", "price": 200.5,
 "usd": 1000, "stop_loss_pct": 2, "id": "AAPL-1730000000000-buy"}
```

| שדה | חובה | ערכים |
| --- | --- | --- |
| `secret` | כן | `WEBHOOK_SECRET` |
| `action` | כן | `buy`, `sell`, `close` (מכור הכול) או `price` (רק עדכון מחיר, לבדיקת Stop Loss) |
| `symbol` | כן | למשל `AAPL` או `BTCUSDT` (קידומת כמו `NASDAQ:` מוסרת) |
| `price` | כן | המחיר שבו "מבוצעת" הפקודה |
| `qty` / `usd` | לא | כמות או סכום. בלי שניהם: `DEFAULT_ORDER_USD` |
| `stop_loss` / `stop_loss_pct` | לא | מחיר Stop, או אחוז מתחת למחיר הקנייה |
| `id` | מומלץ | מזהה ייחודי להתראה, למניעת כפילויות |

## מגבלות שכדאי להכיר

- **ביצוע במחיר האות.** הסימולטור "ממלא" את הפקודה בדיוק במחיר שהגיע מ־TradingView, בלי החלקה (slippage) ובלי מרווח קנייה/מכירה. בשוק אמיתי התוצאות יהיו קצת פחות טובות.
- **Stop Loss נבדק רק כשמגיע מחיר.** השרת לא מושך מחירים בעצמו (בכוונה, כדי שלא יהיו לו שום חיבורים החוצה). לכן הסקריפט שולח מחיר בכל סגירת נר. ה־Stop מתבצע במחיר שהגיע, שיכול להיות נמוך מרמת ה־Stop אם המחיר קפץ.
- **רווח והפסד יומי** נספר מעסקאות סגורות (ממומש) בלבד.
- **בתוכנית החינמית של Render** השרת "נרדם" אחרי 15 דקות בלי פעילות, ו**הנתונים מתאפסים** כשהוא נרדם או מתעדכן. פרטים ופתרון ב[מדריך הפריסה](docs/DEPLOY.md#שמירת-הנתונים-לאורך-זמן).
- זה כלי ללמידה ולתרגול, לא ייעוץ השקעות. הצלחה בסימולטור לא מבטיחה הצלחה בכסף אמיתי.
